# Dispatch API (Supabase)

Requires Node 18+ and the existing CAD Supabase schema. Apply the dashboard's Supabase migrations, including `20261018144157_dispatch_api_rpc.sql`, to the same project used by the frontend. Configure `.env` from `.env.example`, then `npm ci` and `npm start`. On Render use this directory as the service root, `npm ci` as the build command, `npm start` as the start command, and `/health` as the health path. Render supplies `PORT`.

Set `SUPABASE_URL`, `SUPABASE_ANON_KEY` (public anon or publishable key), and `CORS_ORIGIN` (comma separated exact dashboard origins). No MongoDB, Redis, service-role secret, or localhost microservices are required by this API. `/health` calls the public `dispatch_ready` RPC to check Data API connectivity and required CAD schema/functions, returning 503 if unavailable or unconfigured. Project URLs must use HTTPS (HTTP is allowed only for loopback development hosts).

Clients sign in through Supabase Auth and send `Authorization: Bearer <access_token>` on `/api/*`. The API verifies the token with Auth, reads the user's role from `public.profiles`, and forwards the same token for every database request so existing RLS applies. Provision profiles with trusted SQL/admin tooling; signup metadata never authorizes a dispatcher. Legacy login/register endpoints return 410. `/api/auth/me` returns the stored profile.

Active storage uses existing `incidents`, `ambulances`, `hospitals`, `profiles`, and `incident_timeline_events`. Request and response records use the schema's snake_case fields. List endpoints return arrays, nearby/scored endpoints return `{ambulances: [...]}` or `{hospitals: [...]}`. Assignment creation accepts snake_case or camelCase resource IDs and invokes the atomic `dispatch_assign` RPC. Lifecycle status supports PATCH and PUT on `/api/incidents/:id/status`; use CANCELLED rather than deleting incident history. Acknowledgment writes an audit event. Status transitions, milestones, and optional notes are persisted atomically through `dispatch_set_status`, which locks the incident and fleet and rejects invalid transitions. Assignment accept/reject/complete are replaced by explicit incident lifecycle updates (405). Nearby uses geographic straight-line kilometres, and hospital scores are a transparent distance/capacity heuristic, not road travel estimates. Analytics use actual caller-visible rows.

The old `routes/`, `models/`, `config/database.js`, and `scripts/seed.js` are unreferenced legacy MongoDB modules. Do not run their seed script or mount their routes. `server.js` is the only active entry point; importing it never opens a listener. Frontend Supabase Realtime operates separately.

Run `npm test` for HTTP transport contract tests and SQL RPC tests. Transport tests run a local HTTP Supabase fixture, verify forwarded tokens, request bodies, failure handling and authorization; they do not assert live cloud connectivity. Run a deployed smoke check with real user tokens and RLS before serving production traffic.
